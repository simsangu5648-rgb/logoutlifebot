# 로그아웃라이프 봇 (누적 체크인 자동 승급 + 결제전환 DM)

Discord 자체 UI로는 "메시지 개수를 세서 자동으로 역할을 준다"는 걸 할 수 없어서, 최종 프롬프트 STEP 5·6은 실제로 동작하는 봇 코드로 구현했습니다. 이 폴더 통째로 서버에 올리면 바로 돌아가요.

## 이 봇이 하는 일

### 기존 기능

- `#스크린타임-기록`, `#끄고-인증`, `#자연-인증`에 이미지 첨부 메시지를 올리면 카운트 +1 (하루 1회만 인정, 연속이 아니라 **누적**)
- 누적 7회 → `그로우-크루` 역할 자동 부여 + DM
- 누적 30회 → `마스터-크루` 역할 자동 부여 + DM
- 3일 이상 기록이 없으면 압박 없는 톤으로 독려 DM
- 가입 후 D+25 / D+27 / D+29 / D+30에 맞춰 결제 전환 DM 자동 발송 (이미 유료 등급인 사람은 제외)

### 추가된 기능 6종

1. **즉시반응 시스템** — `#충동-sos`에 글이 올라오면 즉시 이모지로 반응하고, 최근 3일 이내 체크인한 그로우/마스터-크루 중 몇 명에게 조용히 DM으로 도움을 요청합니다. (같은 사람에게 너무 자주 알림이 가지 않도록 쿨다운 있음)
2. **데일리 스트릭 대시보드** — 체크인할 때마다 연속일수(스트릭)를 계산해서 저장하고, `#나의-그래프`에서 `!기록`이라고 치면 누적/연속/최고기록/이번 달 횟수를 보여줍니다. 스트릭이 끊기기 직전(전날 체크인 후 오늘 아직 안 함)에는 저녁에 부담 없는 리마인더 DM을 보냅니다.
3. **월간 리포트 카드** — 매달 마지막 날, 그 달에 한 번이라도 체크인한 멤버에게 "이번 달 인증 N회, 최장 연속 M일, 지난달 대비 ±X회" 요약을 DM으로 보냅니다.
4. **승급 알림 & 배지 시스템** — 그로우/마스터-크루로 승급하면 기존 DM에 더해 `#자유수다`에 공개 축하 메시지를 남깁니다. 원치 않는 멤버는 봇에게 DM으로 "알림끄기"를 보내면 본인만 제외됩니다 ("알림켜기"로 다시 켤 수 있음).
5. **온보딩 미션 시퀀스** — 가입 후 D+1 / D+3 / D+7에 맞춰 "오늘의 미션" 안내 DM을 자동으로 보냅니다 (첫 인증 유도 → 커뮤니티 인사 유도 → 그로우-크루까지 남은 페이스 안내).
6. **멘토 하이라이트 시스템** — 그로우/마스터-크루가 쓰 메시지에 지정된 감사 이모지(기본 🙏)가 달리면 "도움 포인트"로 집계되고, 매주 일요일 밤 가장 많이 도와준 멤버를 `#명예의-전당`에서 공개 발표합니다. 누적 포인트도 함께 저장되니 나중에 월간/연간 랭킹 페이지를 만들 때 그대로 쓸 수 있습니다.

세부 채널 이름, 이모지, 발송 시간은 전부 `.env`에서 바꿀 수 있습니다 (`.env.example` 참고).

## 준비물

1. Discord 개발자 포털(https://discord.com/developers/applications)에서 애플리케이션 생성 → Bot 탭에서 봇 생성 → 토큰 복사
2. Bot 탭에서 다음 2개 인텐트(Privileged Gateway Intents)를 반드시 켜기: **SERVER MEMBERS INTENT**, **MESSAGE CONTENT INTENT** (리액션 집계·DM 명령어에 쓰는 인텐트는 특별 권한이 필요 없어 코드에만 추가하면 됩니다)
3. OAuth2 → URL Generator에서 scope: `bot` 체크, 권한: `Manage Roles`, `Send Messages`, `Read Message History`, `Add Reactions` 체크 → 생성된 링크로 서버에 봇 초대
4. **중요**: 서버 설정 > 역할 에서, 봇의 역할을 `그로우-크루` / `마스터-크루` 역할보다 위쪽에 놓아야 합니다. Discord는 자기보다 낮은 역할만 부여할 수 있어요.
5. `#충동-sos`, `#나의-그래프`, `#자유수다`, `#명예의-전당` 채널이 실제 서버에 있는지, `.env`의 채널 이름 설정과 정확히 일치하는지 확인하세요 (이름이 다르면 해당 기능만 조용히 동작하지 않습니다). `#명예의-전당`은 이미 서버에 만들어 두었습니다.

## 설치 및 실행

```bash
npm install
cp .env.example .env
# .env 파일 열어서 토큰/서버ID/역할ID/결제링크 채우기
npm start
```

역할 ID·서버 ID는 Discord 앱에서 설정 > 고급 > 개발자 모드를 켠 다음, 서버 아이콘/역할을 우클릭하면 "ID 복사"가 나옵니다.

## 어디에 올려두나요

24시간 켜져 있어야 하는 봇이라, 로컬 PC보다는 아래 중 하나를 추천해요.

- Railway (railway.app) - 무료 크레딧으로 시작하기 가장 쉬움
- Render (render.com) - Background Worker로 등록
- 저렴한 VPS + `pm2 start index.js`로 프로세스 유지

## 데이터는 어디 저장되나요

`data.json` 파일 하나에 유저별 누적 카운트/마지막 인증일/DM 발송 여부/연속 스트릭/월별 인증 횟수/도움 포인트가 저장됩니다. 별도 DB 설정이 필요 없지만, 그만큼 이 파일이 지워지면 기록도 같이 사라지니 호스팅 서비스에서 파일이 유지되는 볼륨(persistent disk)에 배포하는 걸 권장해요. (Railway/Render 무료 플랜은 재배포 시 파일시스템이 초기화될 수 있으니, 사용량이 늘면 sqlite + 볼륨 마운트나 외부 DB로 옮기는 걸 고려하세요.)

## 전자책 구매자 전용 30일 리부트 챌린지 (폼 방식)

전자책 「REBOOT 30」의 30일 구성(관찰기 Day 1~7 → 공식 확정 Day 8 → 실행기 Day 9~30)을 그대로 따라가는 챌린지입니다. 봇과 대화로 주고받지 않고, 매일 **개인 폼 링크**(`/c/<토큰>`)에서 적고 제출하면 운영자 관리 페이지(`/admin`)에 모입니다.

- 구매자는 랜딩페이지가 알려주는 **입장 링크**(`/join/<토큰>`)로 들어와 디스코드로 로그인하면 서버에 자동 입장 → 리부트-크루 등급 → 챌린지 즉시 시작(오늘이 Day 1, 시작 전 체크 Day 0 먼저).
- 완료 기준은 30일 연속이 아니라 "기록하고 돌아온 날 수". 쉬었다 와도 기록은 그대로이고 멈춘 곳부터 이어갈 수 있어요. 30일(Day 30) 제출 시 마스터-크루.
- 운영자: 매일 아침 9시에 하루 요약 DM, 위기 신호(자해·자살 관련 표현 등)는 즉시 DM. 기록 열람과 답장(봇이 DM으로 전달)은 `/admin`.
- 데이터는 `challenge.json`(영구 볼륨의 DATA_DIR)에 저장되고, 참가자는 폼 화면에서 자기 기록을 직접 삭제할 수 있습니다.
- DM 명령어: 참가자 `!챌린지시작`(내 링크 다시 받기/쉬었다 재개), `챌린지그만`(쉬기), `!구매확인 <코드>`(로그인 연동 없이 입장) · 운영자 `!구매링크`, `!구매링크재발급`, `!챌린지관리`, `!챌린지통계`.
- 설정 값은 `env.example`의 "전자책 구매자 전용 30일 리부트 챌린지" 항목을 보세요.

### 구매자별 1회용 입장 링크 · 환불 회수 (랜딩 서버 연동)

랜딩 서버가 결제를 확인한 직후 봇을 호출하면, 구매 1건마다 **추측 불가능한 1회용 입장 링크**(`/join/<64자 토큰>`)가 발급됩니다. 링크는 처음 로그인한 디스코드 계정 1개에만 연결되고(주문번호 `orderNo`가 유일한 연결 키), 다른 계정이 열면 "이미 사용된 링크"로 막히며, 같은 계정이 다시 열면 자기 챌린지 페이지로 돌아갑니다. 이메일·전화번호 같은 개인정보는 받지도 저장하지도 않습니다. 환불이 나면 같은 방식으로 호출해 링크 무효화 · 등급 회수 · 기록 삭제를 한 번에 처리합니다.

**환경변수**: `LANDING_BOT_SECRET`(랜딩과 공유하는 서명 비밀키, 없으면 API 꺼짐), `LEGACY_JOIN_ENABLED`(기본 `true`; `false`면 예전 공용 링크와 `!구매확인` 차단), `PUBLIC_BASE_URL`(링크의 기준 주소, 필수).

**서명**: 헤더 `X-Signature: sha256=<hex>`, 값은 `HMAC-SHA256(LANDING_BOT_SECRET, "<ts>." + <요청 본문 원문 문자열>)`. 본문의 `ts`(유닉스 초)는 현재 시각 ±5분 이내여야 하고, 서명은 상수시간 비교로 검증합니다. 본문은 보낸 문자열 그대로 서명하세요(서명 후 다시 직렬화하면 안 됩니다).

```js
// 랜딩 서버(Node) 예시
const crypto = require("crypto");
async function callBot(path, payload) {
  const body = JSON.stringify({ ...payload, ts: Math.floor(Date.now() / 1000) });
  const ts = JSON.parse(body).ts;
  const sig = crypto.createHmac("sha256", process.env.LANDING_BOT_SECRET).update(`${ts}.${body}`).digest("hex");
  const r = await fetch(process.env.BOT_BASE_URL + path, {
    method: "POST",
    headers: { "Content-Type": "application/json", "X-Signature": "sha256=" + sig },
    body,
  });
  return r.json();
}
// 결제 검증 직후: const { joinUrl } = await callBot("/api/purchases", { orderNo });
// 환불 직후:      await callBot(`/api/purchases/${orderNo}/revoke`, { orderNo, reason: "고객 환불" });
```

- `POST /api/purchases` — 본문 `{ "orderNo": "…", "ts": 1760000000 }` → `200 { "ok": true, "joinUrl": "<PUBLIC_BASE_URL>/join/<토큰>", "status": "issued" | "claimed" }`. 같은 `orderNo`로 다시 부르면 같은 링크를 돌려줍니다(멱등). 환불된 주문이면 `409 { "ok": false, "status": "revoked" }`. `orderNo`는 영문·숫자·`_`·`-` 1~64자.
- `POST /api/purchases/:orderNo/revoke` — 본문 `{ "ts": …, "reason": "…", "orderNo": "…(권장, 경로와 같아야 함)" }` → `200 { "ok": true, "status": "revoked", "alreadyRevoked": false }`. 링크 무효화, 연결된 계정이 있으면 리부트-크루·마스터-크루 등급 회수 + 챌린지 기록·개인 주소 삭제(개인 주소는 "환불된 구매" 안내만 보임) + 매일 DM 중단 + 운영자 DM. 여러 번 불러도 안전합니다. 같은 계정에 유효한 다른 주문이 남아 있으면 등급·기록은 그대로 둡니다.
- 오류: `400`(잘못된 요청/`orderNo`), `401`(서명 불일치·시간 초과), `409`(환불된 주문), `429`(요청 과다), `503`(`LANDING_BOT_SECRET`/`PUBLIC_BASE_URL` 미설정). 응답은 모두 `Cache-Control: no-store`이고, 토큰·비밀키·기록은 로그에 남기지 않습니다.

**Day 0 동의문**: 버전(`lib/rc-content.js`의 `CONSENT_VERSION`)과 동의 시각을 참가자별 `consent: { version, at }`로 저장합니다(서버가 기록, 클라이언트 값은 무시). 문구를 바꾸면 버전을 올리세요. 이전 동의자는 그대로 두고 관리자 참가자 화면에 `v1(이전)`으로 표시됩니다. 내용은 랜딩 개인정보처리방침 제14조와 같아야 합니다.
